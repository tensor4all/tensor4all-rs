## Protocol and validity

Baseline is pristine merged `66ecc870f0b50254ce031c0c260a2353ff548388`, built
in an isolated target. Candidate code is `04975c44a65ea373086c8f2dbd4b65cd89dde31b`.
Separate executables preserve both builds; each reports its source commit.
Executable SHA-256 values:

- Baseline: `6d382473946bb9bffbb8019f604408dd9f7331826f24831b76a7f2550aad737c`.
- Candidate: `f3c16fcf213541e6fb62172e69a72f76a31db267f89d320a9f68fa65e1fa0aac`.

The existing [TreeACI branch-cost protocol](../README.md#treeaci-branch-cost-attribution-732)
covers 120 cases: f64/Complex64, degrees 2/3/4, four bond profiles, ACI and
cold/warm query batches of 8/32. Three alternating pairs each use three
measurements after an untimed warm-up. Release/default CPU backend, diagnostics
disabled, affinity CPU 2, all Rayon/BLAS/Tenferro threads one. Host: AMD Ryzen
9 6900HX, virtualized Linux, Rust/Cargo 1.98.1. No numerical or compiler job
overlaps timing. The scalar builder batches reuse axis metadata; the scalar
accumulator preserves multiplication/addition order through a borrowed iterator.

All 120 cases pass oracle checks; all 360 paired runs have identical baseline/
candidate evaluated-point counts and maximum relative errors. Largest relative
oracle error is 2.6552555410876038e-15. There are zero execution, dispersion, load or
frequency validity failures under the existing runner settings. The verdict is
`DESCRIPTIVE`, with no preregistered regression threshold. This does not establish
a production speedup or certify non-regression on every workload. Query-only
readout is an unchanged negative control; its timing spread remains visible.
