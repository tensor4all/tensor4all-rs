## Reproduction

Run from the repository root after fetching the pinned history:

```bash
python3 scripts/backtest-file-growth.py \
  --base 22621f25e6357ebf147a062060f252162743579c --count 20 \
  --output-json /tmp/t4a-file-growth-backtest.json
```

The JSON output records every PR number, base/head commit, and file-level finding.
The Markdown table above is generated by that command. The pinned tip was current
`origin/main` when sampled on 2026-11-03; newer landings require a new sample.
GitHub PR metadata confirmed these PR numbers and merge commits. Standard squash
and merge messages identify the landings, including PRs #1080, #1073 and #1072
that used merge commits.

For a first-crossing-only comparison on this sample, repeat the command with
`--large-limit 1000000000` (above every file size in the sample). This yields
3 reminders in 3/20 PRs. All 20 growth-only verdicts pass in both configurations;
other repository checks are not part of this backtest's verdict.

## Review of the reminders

There are 3 first-crossing reminders and 8 already-large reminders, spread across
8 distinct PRs. No reminder in this sample comes from a conventional test path,
recognized generated file, pure rename, unchanged file, or net-shrinking file.
All thresholds remain provisional.

- PR #1093 adds layout refinement and patchwise operation helpers to
  `partitioned_tree_tn.rs` (803 -> 1169). This is a useful point to discuss a
  responsibility boundary; a split is not automatically necessary.
- PR #1090 adds residual-error reporting and documentation to `matrix_luci.rs`
  (979 -> 1006). The trigger is accurate, but this is a coherent existing concern;
  a brief explanation is sufficient.
- PR #1087 adds logical patch-order metadata and its accessors to
  `subdomain_tree_tn.rs` (968 -> 1006). It is another threshold crossing within an
  existing responsibility, rather than evidence that line-count splitting helps.
- The substantial already-large additions are digest support in PR #1100,
  einsum-spec caching in #1092, and tensor adoption support in #1082. PR #1081
  grows an existing evaluator kernel. These mark large files for inspection,
  without deciding whether their additions belong elsewhere.
- The noisy end of the already-large rule is concrete: PR #1082 adds one `mod`
  declaration to `treetn/mod.rs` (2486 -> 2487), and PR #1080 grows `idx_tensor.rs`
  by three net lines (9452 -> 9455) during encapsulation work. Requiring a fresh
  size explanation for these edits is likely low value.

The evidence favors discussing whether to enable first-crossing reminders alone,
or to require a meaningful growth amount before reminding on an already-large
file. This experiment intentionally does not choose that amount, finalize either
threshold, demand a PR-body section, or enable automatic comments. A maintainer
judgment about usefulness is still needed; the 8/20 warning rate is not an
empirical false-positive rate.
